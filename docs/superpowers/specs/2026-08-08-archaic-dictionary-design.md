# KJV 고어 사전 (암송 결과 화면)

작성일: 2026-08-08 (2026-08-08 개정: 일반 단어 커버리지 확대)
대상: verse-flutter (앱 전용). 웹은 범위 밖.

## 목적

KJV 본문은 17세기 고어(thee, hath, saith, unto …)뿐 아니라 한국인 학습자에게
낯선 일반 영단어도 많다. 암송 결과 화면에서 구절의 단어를 탭하면 뜻을 볼 수 있게
해서, 학습자가 앱을 벗어나 검색하지 않고 그 자리에서 이해하도록 한다.

## 범위

포함:
- 암송 결과 화면(`MemorizePhase.result`)의 구절 단어 탭 → 사전 바텀시트
- 완벽 정답(초록) 결과에도 구절 카드를 노출해 사전에 접근 가능하게 함
- **KJV 본문에 실제 등장하는 단어 전체**(고어 + 일반 어휘)를 아우르는 번들 사전 데이터
  (현대영어 대응 / 영영 정의 / 한글 설명). 두 계층으로 구성 — 아래 "데이터" 참고

제외 (후속 확장 여지로만 남김):
- 읽기 화면, 암송 입력 중 화면
- KJV 본문에 등장하지 않는 단어까지 다루는 범용 영한사전, 스트롱 코드 원어 사전
- 사전 검색 화면, 즐겨찾기한 단어 등 별도 진입점
- 서버 동기화 (사전은 정적 에셋)

## 데이터

두 계층으로 구성하되 **런타임 스키마는 동일**하다 — 조회 계층(`ArchaicDictionary`)은
어느 계층에서 왔는지 구분하지 않는다.

| 계층 | 대상 | 출처 | 검수 방식 |
|---|---|---|---|
| A. 고어 | 대표 고어 약 300개 (thee/thou/hath/saith …) | AI 생성 | 사람이 300줄 전수 검수 |
| B. 일반 어휘 | KJV 본문에 등장하는 그 외 전체 단어 (약 1만~1만2천개) | 외부 공개 데이터셋 가공 | 자동 파이프라인 + 표본 검수 (아래 참고) |

계층 B를 사람이 전수 검수하는 것은 비현실적이다(수천 단어 대상 며칠~몇 주 소요).
대신 신뢰할 수 있는 기존 사전 데이터를 그대로 가공해서 쓰고, 사람은 표본만 확인한다.
이 비대칭(A는 전수, B는 표본)이 이번 데이터 정책의 핵심이다.

### 산출물

`assets/dictionary/archaic_kjv.json` — 소문자 표제어를 키로 하는 단일 객체. 계층
A/B 항목이 같은 파일, 같은 스키마로 합쳐진다(런타임에서 구분할 필요가 없으므로
파일도 나누지 않는다).

```json
{
  "hath": {
    "modern": "has",
    "en": "third-person singular present of have",
    "ko": "가지다·~했다 (have의 3인칭 단수 고어형)"
  },
  "thee": {
    "modern": "you",
    "en": "objective case of thou; you (singular)",
    "ko": "너를·너에게 (2인칭 단수 목적격)"
  },
  "shepherd": {
    "modern": "shepherd",
    "en": "a person who tends and herds sheep",
    "ko": "양치기, 목자"
  }
}
```

세 필드 모두 필수. `modern`은 짧은 현대영어 대응/동의어(고어가 아닌 일반 단어는
자기 자신이거나 쉬운 동의어), `en`은 한 문장 영영 정의, `ko`는 한 문장 한글 설명.

### 계층 A (고어) 생성 절차

1. KJV 본문 전체에서 토큰 빈도표 추출 (`tool/` 아래 일회성 스크립트).
   본문 원천은 백엔드의 `bible_verses` 테이블이며, 여기서 뽑은 전문을 스크립트 입력으로 쓴다
2. 현대 영어에 없거나 의미가 다른 고어 후보를 선별하고 빈도순 정렬
3. 상위 300개에 대해 AI로 세 필드를 배치 생성
4. **사람이 300줄 전수 검수** — 검수되지 않은 항목은 앱에 넣지 않는다

빈도 상위 300개로 고어 출현의 대부분을 덮는다는 가정에 근거한다. 롱테일은
계층 B가 일반 어휘로 흡수하므로 계층 A를 억지로 늘리지 않는다.

### 계층 B (일반 어휘) 생성 절차

1. **범위 확정**: KJV 본문 전체에서 계층 A에 없는 고유 단어(소문자, 알파벳만)를
   전부 추출한다. 이 목록이 계층 B의 상한이다 — KJV에 나오지 않는 단어는
   애초에 후보로 만들지 않는다(수집 범위를 KJV 어휘로 한정하기로 결정함)
2. **한글 뜻(`ko`)**: [kengdic](https://github.com/garfieldnate/kengdic) —
   영한사전 데이터셋(TSV, `surface`/`gloss` 필드). MPL 2.0 또는 LGPL 2.0+ 이중
   라이선스로, `surface`가 KJV 단어 목록과 일치하는 행의 `gloss`를 `ko`로 쓴다
3. **영영 정의(`en`) + 현대영어 동의어(`modern`)**: Princeton WordNet(퍼블릭 도메인).
   표제어의 첫 synset 정의를 `en`으로, 같은 synset의 대표 동의어(표제어 자신일 수 있음)를
   `modern`으로 쓴다
4. kengdic과 WordNet 양쪽에서 매칭되지 않는 단어(고유명사, 지명, 극히 드문 변형 등)는
   **버린다** — 데이터가 없는데 항목만 만들면 빈 필드가 생기고, 그건 노출하지 않는다
5. **표본 검수**: 자동 병합 결과에서 무작위 100개 + 빈도 상위 50개를 사람이 눈으로 확인해
   매칭 오류(동음이의어 오매칭 등)가 없는지 점검한다. 문제 패턴이 발견되면 해당 패턴만
   규칙으로 걸러내고 전수 재검수는 하지 않는다

### 라이선스 고지

kengdic 데이터를 가공해 재배포하므로 앱 내 크레딧/오픈소스 고지 화면에 kengdic
출처와 라이선스(MPL 2.0 또는 LGPL 2.0+)를 명시해야 한다. WordNet은 퍼블릭
도메인이라 고지 의무는 없지만 관례상 함께 표기한다. (고지 문구 삽입 위치는
기존 오픈소스 라이선스 화면이 있으면 거기 추가 — 없으면 이번 작업 범위 밖으로
남기고 별도 처리)

## 아키텍처

### `lib/core/dictionary/archaic_dictionary.dart`

단일 책임: 사전 에셋을 로드하고 단어를 조회한다.

```dart
class ArchaicEntry {
  final String word;    // 표제어(소문자)
  final String modern;
  final String en;
  final String ko;
}

class ArchaicDictionary {
  Future<void> load();                 // 에셋 1회 로드
  ArchaicEntry? lookup(String token);  // 정규화 후 조회, 없으면 null
}
```

- 정규화: 소문자화 + 앞뒤 구두점/따옴표 제거. 어미 변형 추론은 하지 않는다
  (필요한 변형은 표제어로 직접 등재한다)
- 약 1만~1만2천 항목 규모. 메모리 `Map` 하나로 충분하다(문자열 위주 데이터라
  수 MB 내외) — drift 테이블을 만들지 않는다. 항목 수가 실제 조회 성능이나
  앱 시작 시간에 문제를 일으키면 그때 재검토한다
- 앱 전역에서 한 번만 로드되도록 Riverpod provider로 노출. 로드 실패 시
  빈 사전으로 동작 — 사전이 없다고 암송이 막히면 안 된다

### UI 변경

**결과 화면 구절 카드**

현재 `_MissedWordsCard`는 `if (!isGreen)` 조건으로만 렌더링되고 오답 단어를
빨강+실선 밑줄로 표시한다. 이를 다음과 같이 바꾼다.

- 초록 결과에도 같은 카드를 렌더링한다. 초록일 때는 오답 표시가 없는 읽기 전용
  형태이고 제목 문구도 "놓친 단어"가 아닌 중립 문구를 쓴다
- 각 단어 위젯을 `GestureDetector`로 감싼다. **사전에 등재된 단어만** 탭에 반응한다.
  등재되지 않은 단어를 눌러 아무 일도 없으면 고장으로 읽히기 때문이다
- 등재 단어에는 약한 어포던스(점선 밑줄)를 준다. 오답 표시(빨강 + 실선 밑줄)와
  선이 겹치므로, 오답이면서 등재된 단어는 오답 표시를 우선하고 어포던스는
  색으로만 구분한다

**사전 바텀시트**

- 탭한 단어 → `showModalBottomSheet`
- 내용 순서: 표제어 / 현대영어 대응 / 영영 정의 / 한글 설명
- 세로로 길어질 수 있으므로 시트 내부는 스크롤 가능하게 한다
  (`DraggableScrollableSheet` 또는 스크롤 가능한 본문)
- 픽셀 팔레트를 따른다: `p.surface` 배경, 2px `p.border`, 하드 그림자, Galmuri 계열

### 문자열

시트 라벨과 중립 제목 문구는 `l10n`에 추가한다. 한/영 모두 채운다. 사전 항목
내용(modern/en/ko)은 에셋 데이터이며 l10n 대상이 아니다.

## 에러 처리

| 상황 | 동작 |
|---|---|
| 에셋 누락·JSON 파싱 실패 | 빈 사전으로 로드. 탭 어포던스가 아무 데도 안 뜨고 결과 화면은 정상 동작 |
| 조회 결과 없음 | 애초에 탭 반응하지 않음 (등재 단어만 탭 가능) |
| 항목에 필드 누락 | 로드 시 해당 항목을 버린다. 부분 렌더링하지 않는다 |

## 테스트

- `ArchaicDictionary`: 정규화(대문자, 앞뒤 구두점, 따옴표) 조회, 미등재 단어 null,
  깨진 JSON에서 빈 사전 반환
- 에셋 데이터 검증 테스트: 모든 항목이 세 필드를 비어 있지 않게 갖는다, 키가 소문자다,
  항목 수가 최소 기대치(예: 5,000) 이상이다 — 계층 B 파이프라인이 조용히 아무것도
  못 만들고 빈 파일에 가까운 걸 산출하는 회귀를 잡기 위함
- 위젯 테스트: 초록 결과에서 구절 카드가 렌더링된다, 등재 단어 탭 시 시트가 열리고
  미등재 단어 탭은 시트를 열지 않는다

## 공수 추정

| 작업 | 추정 |
|---|---|
| 계층 A: 빈도 추출 + 후보 선별 + 300개 생성 | 1일 |
| 계층 A: 사람 검수(300줄 전수) | 1일 |
| 계층 B: KJV 전체 어휘 추출, kengdic/WordNet 확보·가공·병합 스크립트 | 1~1.5일 |
| 계층 B: 표본 검수(150개) + 병합 규칙 보정 | 0.5일 |
| `ArchaicDictionary` + provider + 테스트 (스키마 동일, 계층 A 때와 큰 차이 없음) | 0.5일 |
| 결과 카드 초록 노출 + 탭 + 바텀시트 + l10n | 1~1.5일 |
| 라이선스 고지 문구 추가 | 0.5일 |

합계 6~7일. 계층 A 검수(1일)와 계층 B 스크립트 작업(1~1.5일)은 서로 다른 사람이
동시에 진행할 수 있으면 총 기간은 줄어든다.

## 후속 확장 (이번 범위 아님)

반나절 규모다.

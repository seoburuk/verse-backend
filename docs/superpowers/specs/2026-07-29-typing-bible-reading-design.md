# 타자 성경통독(Reading) 설계 v2 (2026-07-29)

`verse-flutter`에 두 번째 코어 루프를 추가한다: 절 원문을 보면서 타이핑으로
따라 치는 성경통독. 암송(고강도·하트 소모·채점)과 대등한 트랙으로,
플랜 시스템을 공유하되 진행 기록·성취는 분리한다.

**이 문서는 `2026-07-27-typing-bible-reading-design.md`를 대체한다.** 그 스펙은
플랜 관리 구현 전에 작성되었고, 통독을 완전히 새로운 타이핑 엔진으로 설계했다.
이 v2는 코드베이스를 다시 읽고 두 가지 사실을 반영해 재설계한 것이다:

1. **"본문 보고 따라 치기"는 이미 앱에 있다** — 딕테이션 모드가 그것이다.
   통독은 그것을 플랜으로 장 단위로 돌리는 것이다.
2. **딕테이션 시도는 이미 서버로 동기화된다** — `sync_service.dart`의
   `dictation` 가드는 로컬 `progress` 쓰기만 건너뛸 뿐, `attempt_queue` → 서버
   POST는 그대로 탄다. 따라서 v1이 만들려던 `reading_progress` 서버 테이블과
   `POST /sync/reading`은 둘 다 불필요하다.

**전제:** 플랜 관리·범위 선택(`2026-07-27-plan-management-design.md`)이 구현되어
`main`에 머지된 코드베이스를 가정한다(verse-flutter `c58960d`). 통독 플랜은 그
플랜 레일에 `mode` 하나를 얹는 것이다.

## 왜 이 기능인가

- 콘텐츠가 이미 있다. 구약 39권·신약 27권 코스에 KJV 전체 절이 적재되어 있다.
  통독은 새 콘텐츠 파이프라인이 필요 없다.
- 암송은 하드코어 소수의 습관이지만 통독·필사는 주류 실천이다. 실패 없는
  저강도 루프가 생기면 "오늘은 지쳤으니 통독만" 하는 날에도 스트릭이 이어진다.
- 세션이 길어(영어 한 장 10~20분) 체류시간 기반 수익화가 암송보다 안정적이다.

## 결정 사항

1. **딕테이션과 통독은 둘 다 남는다.** 딕테이션 = 암송 화면 안의 절 단위 모드,
   통독 = 플랜 기반 장 단위 트랙. 딕테이션의 "노힌트 버전"은 만들지 않는다.
2. 타이핑 텍스트는 **KJV 영어 원문**. 한글 성경 적재는 제외.
3. **글자 단위로 오타를 차단한다.** 틀린 글자는 입력 자체가 무시되고 커서가
   정지한다. 항상 정확한 텍스트가 완성된다.
4. **입력 판정은 영숫자만 요구한다**(§3.2 b안). 대소문자 무시, 구두점·공백은
   커서가 자동 통과. 화면 표시는 원문 그대로.
5. **제출 버튼 없이 자동 전진.** 마지막 영숫자를 맞게 친 순간 절이 완료된다.
6. **통독에는 목숨 게이트가 없다.** 실패할 수 없는 루프다.
7. 채점·시도 기록 파이프라인은 **재사용한다**. 통독 시도는 `mode='reading'`으로
   `attempt_queue`에 쌓여 기존 동기화를 탄다.
8. 성취는 **픽셀 성경책장** — 66권 그리드, 장을 칠수록 책이 차오른다.
9. 책장 위치는 **카드 탭을 세그먼트로 확장**(`[카드 | 책장]`). 탭 구조 변경 없음.
10. 광고는 **장 경계 우선 + 절 경계 백업**의 전면광고. 보상형은 제외.
11. 플랫폼은 **Flutter 모바일만**. 웹 이식은 검증 후.
12. 암송·통독 플랜은 **완전 대칭** — 각자 생성·변경·포기·마감 수정 모두 가능.
13. **통독 진행은 서버 동기화한다** — 재설치/기기 변경 시 책장이 복원되어야 한다.

## 1. 데이터 모델

### 1.1 로컬 (drift, 스키마 v3 → v4)

`memorization_plan`에 컬럼 하나:

```dart
TextColumn get mode => text().withDefault(const Constant('memorize'))(); // memorize|reading
```

신규 테이블:

```dart
class ReadingProgress extends Table {
  IntColumn get courseItemId => integer()();
  DateTimeColumn get typedAt => dateTime()();

  @override
  Set<Column> get primaryKey => {courseItemId};
}
```

마이그레이션은 기존 패턴 그대로:

```dart
if (from < 4) {
  await m.addColumn(memorizationPlan, memorizationPlan.mode);
  await m.createTable(readingProgress);
}
```

**암송 `progress`와 절대 섞지 않는다.** `progress.cleared`는 "외웠다"는 뜻이고
카드 보상·암송 통계의 근거다. 통독으로 타이핑한 절을 cleared 처리하면 그 지표가
전부 오염된다. 통독 플랜의 진행률과 책장은 `reading_progress`만 센다.

`reading_progress`는 로컬 조회 전용 인덱스다 — 서버의 진실 소스는 `attempts`
테이블이고(§1.2), 이 테이블은 책장·진행바가 네트워크를 기다리지 않게 하는
오프라인 우선 캐시 역할을 한다.

**스트릭은 공유한다.** 어느 트랙이든 하루에 활동하면 스트릭이 이어진다 —
리텐션 자산은 통합, 성취 자산은 분리가 원칙이다.

### 1.2 서버 (verse-backend)

**DB 마이그레이션 없음.** `attempts.mode`는 이미 문자열 컬럼이고, 통독 진행은
기존 `attempts` 테이블에 그대로 쌓인다.

| 위치 | 변경 |
|---|---|
| `internal/domain/attempt.go` | `ModeReading Mode = "reading"` 추가 |
| `attempt_service.go:54` | 목숨 0이어도 `ModeDictation`·`ModeReading`은 시도를 거부하지 않음 |
| `attempt_service.go:113` | `ModeDictation`·`ModeReading`은 비-green이어도 목숨을 소모하지 않음 |
| `attempt_service.go:84` | 진도 갱신 제외 대상에 `ModeReading` 추가 |

**목숨 분기는 필수다.** 현재 서버는 mode와 무관하게 목숨을 검사·소모하는데,
이는 딕테이션에도 이미 있는 불일치다 — 클라이언트는 딕테이션에서 목숨을 깎지
않지만(`lives_streak_repository.dart:48`) 서버는 깎는다. 고치지 않으면 목숨이
0이 된 순간 통독 시도가 전부 `skipped_no_lives`로 거부되어 영영 동기화되지
않고, 책장과 재설치 복원이 깨진다. 이 수정은 딕테이션의 기존 버그도 함께
해결한다.

신규 엔드포인트 1개(인증 필요, 기존 미들웨어 재사용):

- `GET /sync/reading` — 사용자의 `attempts` 중 `mode='reading'`인 고유
  `course_item_id` 목록과 최초 `created_at`을 반환한다. 재설치 복원용.
  응답 `{"items":[{"course_item_id":N,"typed_at":"..."}]}`.

업로드용 엔드포인트는 만들지 않는다 — 기존 배치 attempts POST가 그 역할을 한다.

### 1.3 PlanRepository

```dart
activePlan({String mode = 'memorize'})
planView({String mode = 'memorize'})
createPlan({..., String mode = 'memorize'})
```

**모드별 활성 플랜 1개씩.** 암송 1 + 통독 1 동시 진행이 최대이며, 같은 모드로
두 개는 만들 수 없다(새로 만들면 기존 것을 변경/포기 플로우로 정리).

`PlanView.clearedVerses`는 모드에 따라 집계 소스가 갈린다 — `memorize`는
`progress.cleared`, `reading`은 `reading_progress` 존재 여부. 나머지 파생
계산(`todayTarget`, `expired`, `planComplete`)은 그대로 재사용한다.

`activePlanViewProvider`는 `memorizePlanViewProvider` /
`readingPlanViewProvider` 두 개로 나뉜다.

## 2. 플랜 생성 — 트랙 갈림길

`PlanScopePicker` **앞에** 갈림길 하나를 추가한다:

```
어떻게 할까요?
[🧠 암송 — 외우고 채점받기]   [⌨️ 통독 — 보고 따라 치기]
```

이후 단계는 **전부 재사용**한다: 범위 선택(권 → 장 칩, 기본 1장), 마감(프리셋 +
직접 선택), 하루 절수 미리보기. 차이는 하나뿐 — **통독은 성경 책 경로만
노출한다**(소형 코스·워밍업 섹터는 암송 전용 큐레이션이다).

생성 시 `createPlan(mode: 'reading', ...)`.

## 3. Today 투트랙

플랜 카드를 두 장 스택으로:

- 암송 플랜 카드(기존) + 통독 플랜 카드. 각자 라벨·진행바·D-day·CTA.
- 카드 몸통을 탭하면 — 암송 카드든 통독 카드든 각각 — **기존
  `showPlanSheet`**가 열린다(마감 변경/플랜 변경/플랜 포기). "이어서" CTA는
  현재 구조대로 별도 버튼이라 탭 동작이 충돌하지 않는다.
- 통독 플랜을 포기해도 통독 진행 기록은 남는다(암송과 동일 원칙).
- 카드가 하나도 없으면 기존 빈 상태, 하나만 있으면 그 카드 + 다른 트랙을
  시작하는 작은 링크("통독도 시작하기").
- 오늘 목표는 트랙별로 계산하고 각 카드에 표시한다.
- 마스코트 무드: **둘 중 하나라도 오늘치 완료면 happy.** 저강도 유저도 매일
  성공 경험을 가져가게 한다.

## 4. 통독 화면 (신규)

```
lib/features/reading/
  reading_screen.dart      화면 + 본문 렌더링
  reading_controller.dart  절 큐 · 입력 검증 · 전진
  typing_cursor.dart       순수 로직 (커서 전진/구두점 통과/백스페이스)
```

암송 화면(`memorize_screen.dart`)을 재사용하지 않는다. 그 파일은 이미 903줄이고,
목적이 정반대인 두 루프(암송=긴장, 통독=몰입)를 한 파일에 섞으면 통독 작업이
암송을 깨뜨릴 위험이 생긴다. 재사용하는 것은 화면이 아니라 **로직**이다:
`grading.dart`(69줄 순수 함수), `attempt_queue` 기록 경로, `AdService`, 플랜 레일.

### 4.1 레이아웃

- **상단** — 절 참조(예: `Genesis 1:3`) + 장 진행(`12/31절`).
- **본문** — 절 원문을 크게, 구두점 포함해 그대로 표시. 세 구간으로 칠한다:
  확정(진한 색) / 커서(강조) / 미입력(흐림).
- **입력** — 화면에 보이지 않는 `TextField`가 키 입력만 받고 상태는 본문 위에
  그린다. 소프트 키보드를 띄워두는 용도이므로 `autocorrect: false`,
  `enableSuggestions: false`, `textCapitalization: TextCapitalization.none`을
  건다. 이 셋이 없으면 자동수정·예측입력이 여러 글자를 한꺼번에 갈아끼워
  prefix 검증에 계속 튕긴다.
- **자동 스크롤** — 커서가 항상 화면 안에 보이게 한다(시편 119편 대비).
- **하트 배지 없음.**

### 4.2 입력 규칙

`typing_cursor.dart`에 순수 함수로 분리한다 — UI 없이 테스트 가능해야 한다.

- 사용자가 친 글자가 **다음 영숫자와 일치하면** 커서 전진.
- **대소문자 무시** — `A`도 `a`도 통과.
- 전진 후 **구두점·공백은 자동으로 통과**한다. `light`의 마지막 `t`를 치면
  `light:` 와 뒤따르는 공백까지 한 번에 확정된다.
- **불일치하면 아무 일도 일어나지 않는다** — 입력이 무시되고 커서가 정지한다.
- 백스페이스는 직전 영숫자까지 되돌린다.

이 기준은 기존 `grading.normalize()`(소문자화 + 구두점 제거)와 정확히 일치한다.
통독은 몰입이 상품성인데 모바일에서 구두점을 치려면 키보드 전환이 잦아 마찰이
크다. 화면에는 원문 그대로 보여주므로 "정확한 텍스트가 완성되는" 경험은 유지된다.

### 4.3 절 완료

마지막 영숫자를 맞게 친 순간:

1. 짧은 확인 피드백(초록 펄스 — 기존 `_FxBox` 연출 재사용).
2. `reading_progress`에 기록. **이미 있으면 `typedAt`을 갱신하지 않는다**(첫
   완료 시각 보존).
3. `attempt_queue`에 `mode='reading'`, `clientGrade='green'`으로 적재 → 기존
   동기화 파이프라인 탑승.
4. **제출 버튼 없이 자동으로 다음 절.**

`attempt_queue.tokensJson`에는 암송과 동일하게 **`normalize(절 원문)`의 토큰
배열**을 넣는다(`memorize_controller.dart:331`과 같은 형태). 글자 단위 차단
덕분에 사용자가 친 내용은 원문과 정규화 기준으로 항상 동일하므로, 서버가 같은
`normalize()`로 재채점해도 green이 나와 클라·서버 판정이 일치한다.

글자 단위 차단 때문에 통독 시도는 **항상 green**이다. 채점은 형식적으로 남지만,
"이 절을 통독했다"는 신호로는 오히려 정확하다.

### 4.4 없는 것

**목숨 게이트 없음, 하트 배지 없음, 채점 결과 화면 없음, 재도전 없음.**
통독 화면은 실패할 수 없는 루프다.

### 4.5 장 완료

장의 마지막 절을 치면 장 완료 축하 화면(책장에 한 칸 차오르는 연출) → "다음 장"
또는 종료. 사운드·햅틱은 기존 `Sfx` 설정을 따른다.

## 5. 픽셀 성경책장

카드 탭 상단에 세그먼트 `[카드 | 책장]`을 추가한다(탭 구조·라우트 변경 없음).

- 책장 뷰: 66권을 픽셀 책 스프라이트 그리드로. 각 책의 채움 정도 =
  `그 코스에서 reading_progress에 있는 절 / 전체 절`.
- 미착수는 흐린 실루엣, 진행 중은 부분 채움, 완독은 선명한 책 + 꽂힘 연출.
- 책을 탭하면 장별 진행(장 칩 그리드에 완료 표시) — 플랜 생성의 장 칩 UI와
  동일한 시각 언어를 쓴다.
- 구약/신약 구분은 그리드 섹션 헤더로.

책장은 `reading_progress`만 센다. 암송으로 외운 절은 책장을 채우지 않는다
(성취 자산 분리 원칙).

## 6. 광고

규칙을 **순수 함수 하나**로 분리해 테스트 가능하게 만들고, 상수는 전부 한곳에
모아 나중에 조정만 하면 되게 한다.

```dart
bool shouldShowInterstitial({
  required bool isChapterBoundary,
  required bool isFirstChapter,
  required Duration sinceLastAd,
})
```

| 조건 | 값 |
|---|---|
| 장 경계 | 마지막 광고 후 **3분** 경과 시 노출 |
| 장 내부 절 경계(백업) | 마지막 광고 후 **10분** 경과 시 노출 |
| 첫 장 | **면제** |
| 절 타이핑 중 | 절대 노출 안 함 |

장 경계를 우선 트리거로 두되, 시편 119편(176절)처럼 긴 장에서는 절 경계 백업이
수익을 낸다. 반대로 짧은 장 연타(시편 117편 2절 → 118편)는 3분 가드에 묶인다.
첫 장을 면제하는 이유는 첫 경험에서 광고를 만나면 이탈하기 때문이다.

절을 치는 도중에는 절대 띄우지 않는다. 몰입이 통독의 상품성이고, 작업 중간
강제 노출은 AdMob 정책상으로도 문제가 된다.

기존 `AdService.showInterstitial()`을 그대로 호출한다 — 광고 배관(전면광고 로드,
ATT 권한 요청)은 이미 있고 **빈도 판단만 새로 얹는다.** 광고가 준비되지 않았으면
조용히 무시되어 진행 흐름을 막지 않는다(기존 동작).

**선행 과제 — UMP 동의폼은 이번 범위 밖이다.** EEA 사용자에게는 광고 노출 전
동의 수집이 필수인데 현재 미구현이다. 통독이 광고 노출을 크게 늘리므로 별도
작업으로 처리하되 **출시 전에는 끝나야 한다.**

**구독 연결:** 전면광고를 정기적으로 보는 통독 유저가 "광고 제거" 구독의 최우선
전환 대상이다(`docs/subscription-implementation-plan.md`).

## 7. 동기화와 복원

업로드는 배관이 거의 필요 없다. 통독 절 완료 시 `attempt_queue`에
`mode='reading'`으로 쌓으면 기존 `syncPendingAttempts`가 그대로 배치 전송한다.

| 위치 | 변경 |
|---|---|
| `sync_service.dart:91` | `mode != 'dictation'` → `dictation`·`reading` 둘 다 progress 쓰기 제외 |
| `session_sync_coordinator.dart:53` | `onLoginSuccess`에 통독 복원 한 줄 추가 |

**로컬 기록은 즉시** 한다 — `reading_progress`에 바로 써서 진행바·책장이
네트워크를 기다리지 않는다. 오프라인 우선 원칙 그대로다.

**복원**은 로그인 직후 1회 `GET /sync/reading`으로 서버 목록을 받아 **로컬에
없는 것만 삽입**한다. 게스트→로그인 승계는 이미 구현된 경로를 그대로 탄다.

**플랜 자체는 로컬 전용으로 남긴다** — 암송 플랜도 로컬 전용이라 일관된다.
동기화 대상은 진행 기록뿐이다.

## 8. 엣지 케이스

| 상황 | 처리 |
|---|---|
| 매우 긴 절(시편 119:1 등) | 커서 자동 스크롤로 항상 화면 안에 |
| 이미 통독한 절을 다시 침 | `typedAt` 갱신 안 함(첫 완료 시각 보존). 진행률 불변, 재타이핑 자체는 허용 |
| 장 중간 이탈 | 친 절까지만 기록. 다음에 그 장을 이어서 |
| 원문의 유니코드 따옴표·이탤릭 표기 | 표시는 원문 그대로. 대조는 영숫자만 보므로 자동 해결 |
| 오프라인 | 전부 로컬 동작. 실패는 Today의 기존 동기화 배너로 알림 |
| 비로그인 사용자 | 로컬에만 쌓이고 책장도 정상 동작. 재설치 시 유실 — 로그인을 권하는 지점(강제하지 않는다) |
| 통독 플랜 포기 | `reading_progress`는 남는다. 책장도 그대로 |
| 광고 미로드 | `showInterstitial()`이 조용히 무시(기존 동작) |

## 9. 테스트

**순수 함수** (UI 없이 검증)

- `typing_cursor` — 정타 전진 / 오타 무시 / 구두점 자동 통과 / 대소문자 무시 /
  백스페이스 / 절 끝 도달
- `shouldShowInterstitial` — 3분 미만이면 false / 장 내부 10분 규칙 / 첫 장 면제 /
  타이핑 중 false

**저장소**

- `reading_progress` — 기록, 중복 시 `typedAt` 불변, 코스별 집계,
  `progress`와 독립임을 검증
- `PlanRepository` — 모드별 활성 플랜 1개씩, 모드별 집계 소스 분리

**동기화**

- `mode='reading'` 배치 업로드, progress 미갱신, 로그인 시 서버 병합

**위젯**

- 투트랙 Today 카드 2장, 통독 화면 커서 3구간 표시, 책장 채움 비율

**백엔드**

- `ModeReading`이 목숨을 검사하지도 소모하지도 않음
- `ModeReading`이 progress를 갱신하지 않음
- `GET /sync/reading` 핸들러

## 10. 구현 단계 분할

각 단계가 **그 자체로 동작하는 소프트웨어**가 되게 나눈다.

**Phase A — 통독 코어 (로컬 전용)**
§1.1 mode 컬럼·`reading_progress` 테이블, §2 트랙 갈림길, §3 투트랙 Today,
§4 통독 화면. 이 단계만으로 통독이 완전히 동작한다(오프라인).

**Phase B — 책장 + 서버 동기화**
§5 픽셀 성경책장, §1.2 백엔드 mode·목숨 분기·`GET /sync/reading`, §7 동기화·복원.
책장이 생겨야 동기화 복원의 가치가 눈에 보이므로 함께 간다.

**Phase C — 광고**
§6. Phase A·B가 끝나 통독이 실제로 돌아가는 것을 확인한 뒤 얹는다.

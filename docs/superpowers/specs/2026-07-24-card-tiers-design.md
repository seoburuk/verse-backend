# 카드 등급(브론즈~레전드) 설계 (2026-07-24)

기존 카드 도감(`2026-07-23-card-collection-design.md`, 구현 완료)에 **등급**을 넣는다.
카드는 이제 "장(章)을 완주하면 해금"이 아니라, **그 주제와 관련된 절 묶음을 얼마나 외웠는가**로
브론즈에서 레전드까지 올라간다.

- **대상**: `verse-flutter/` 앱 전용. 오프라인 우선.
- **전제**: 카드 목록·설명·관련 절은 계속 손으로 고치는 데이터다. 이 스펙은 **스키마와 판정 로직**까지
  책임지고, 실제 문구와 절 목록은 뒤에 `cards.json`만 고쳐 채운다.

---

## 1. 왜 바꾸나

현재 해금 조건은 "그 섹션(=장)의 모든 절을 외웠는가"다. 문제:

- 장 하나가 25~31절이라 **첫 카드를 보기까지 너무 오래 걸린다**.
- 카드와 주제의 연결이 느슨하다 — 비둘기 카드가 창세기 8장에 걸려 있을 뿐,
  "비둘기에 관한 절"과는 무관하다.

바꾼 뒤: 비둘기 관련 절 중 **1절만 외워도 브론즈 카드가 바로 등장**하고,
관련 절을 **다 찾아 외우면 레전드**가 된다. 카드가 일찍 나와 동기가 붙고,
등급이 남아 있어 마무리할 이유가 생긴다.

---

## 2. 카탈로그 스키마 — `unlock` → `verses`

`assets/cards/cards.json`의 각 항목에서 `unlock` 객체를 제거하고 `verses` 배열을 넣는다.

```json
{
  "id": "dove",
  "name": "비둘기",
  "name_en": "Dove",
  "kind": "animal",
  "description": "",
  "description_en": "",
  "image": "",
  "verses": ["1:8:8", "1:8:9", "1:8:10", "1:8:11", "1:8:12"]
}
```

- `verses`: `"책번호:장:절"` 문자열 배열. 그 카드의 주제와 관련된 절들.
  문자열 형태를 택한 이유는 **손으로 고치고 diff로 읽기 쉽기** 때문이다.
- 해석되지 않는 ref(오타, 범위 밖)는 **조용히 건너뛴다** — 오타 하나로 레전드가 영영
  막히면 안 된다. 대신 §6의 테스트가 오타를 잡는다.
- `verses`가 비어 있거나 전부 해석 불가면 그 카드는 **영원히 등급 없음**이고 화면에 나오지 않는다.

**작성 지침: 카드당 관련 절을 4개 이상 둔다.** 2~3절뿐이면 중간 등급이 건너뛰어진다(§3).

번들 코스는 KJV 31,102절을 모두 담고 있으므로, 어떤 절을 적어도 외울 수 있는 대상이 된다.

---

## 3. 등급 사다리

임계값은 **코드가 아니라 데이터**로 둔다 — `assets/cards/tiers.json`:

```json
[
  { "id": "silver", "minRatio": 0.34 },
  { "id": "gold",   "minRatio": 0.67 }
]
```

중간 두 단계만 데이터로 둔다. 브론즈("1개 이상")와 레전드("전부")는 비율이 아니라 규칙 자체다.

판정 규칙(순수 함수):

| 외운 절 | 등급 |
|---|---|
| 0개 | 없음 — 도감에 나오지 않는다 |
| 1개 이상 | 브론즈 |
| 34% 이상 | 실버 |
| 67% 이상 | 골드 |
| **전부** | 레전드 |

- **브론즈는 "1개 이상"**으로 판정한다 — 0개가 브론즈로 새지 않게.
- **레전드는 "전부"**로 판정한다. 반올림으로 한 절 남기고 레전드가 되면 안 된다.
- 관련 절이 2개면 1개 외웠을 때 0.5 → 곧바로 실버다(0.34 이상, 0.67 미만). **브론즈가
  건너뛰어지는 것**은 의도한 절충이고, §2의 "4절 이상" 지침으로 완화한다.

---

## 4. 판정 — 새 테이블 없음

기존 `CourseItems` + `Progress` 파생을 유지한다.

1. `cleared`인 `course_items`에서 `(book, chapter, verse)` 집합을 한 번에 뽑는다.
2. 카드별로 `verses`와의 **교집합 개수**를 센다.
3. 개수 ÷ 해석 가능한 총 개수 → 등급.

같은 절이 여러 코스(주제 코스 + 책 코스)에 중복 존재하는데, **하나라도 `cleared`면 외운 것**으로 친다.

기존 `CardRepository.completedSectionIds()` / `cardForSection()`은 더 이상 쓰이지 않으므로 제거한다.

---

## 5. 연출 — 등급이 오를 때마다 뒤집기

**섹션 완료 화면(`SectionCompleteScreen`)의 뒤집기는 걷어낸다.** 해금 단위가 섹션이 아니게 됐다.

대신 **암송 결과 화면**(`memorize_screen.dart`의 `_ResultView`)에 붙인다.
이미 마일스톤 축하가 같은 자리·같은 조건(green 판정, 받아쓰기 제외)으로 동작하므로 그 패턴을 따른다.

- 방금 외운 절이 속한 카드들의 등급을 다시 계산한다.
- **등급이 올랐다면 카드 뒷면이 뜨고, 탭하면 뒤집혀 앞면이 공개된다.**
- 첫 등장(브론즈)이든 실버·골드·레전드로 오른 것이든 **똑같은 뒤집기**다.
  분기가 없어 `CardFlip`을 그대로 재사용하고, 앞면에 등급이 함께 보이므로
  뒤집는 순간이 곧 "올랐다"는 확인이 된다.
- 한 절이 여러 카드의 등급을 동시에 올릴 수 있다. 그 경우 **한 장씩 차례로** 뒤집는다.

**중복 축하 방지**: 기존 `revealed_cards`(카드 id만)를 **id + 등급** 기록으로 바꾼다.
같은 등급은 두 번 축하하지 않고, 등급이 오르면 다시 뒤집을 수 있다.
옛 키는 의미가 달라졌으므로 새 키를 쓰고 옛 값은 무시한다.

---

## 6. 도감 화면

- 타일: 등급 색 테두리 + 등급 이름.
- 상세: **그림 · 이름 · 설명 · 등급**, 이 넷뿐.

**상세에 관련 절 목록을 두지 않는다.** 외운 절 표시도, 남은 절도, "3/5" 같은 진행 숫자도 없다.

- 이유: 기존 도감 스펙의 원칙과 같다 — 빈칸을 보여주고 채우라 재촉하지 않는다.
  화면이 알려주는 것은 "지금 이 카드가 실버다"까지고,
  **골드로 가려면 뭘 더 해야 하는지는 앱이 알려주지 않는다.** 관련 절을 찾는 건 사용자 몫이다.
- 대가: 레전드를 목표로 삼은 사용자는 남은 절을 스스로 추적해야 한다. 의도한 절충이다.

잠긴 카드 숨김·전체 수집 카운터 없음은 기존 스펙 그대로 유지한다.

---

## 7. 테스트

- **등급 판정 순수 함수**: 0개→없음, 1개→브론즈, 전부→레전드, 34%/67% 경계,
  관련 절 2개짜리가 실버를 건너뛰는 것.
- **교집합 판정**: 같은 절이 여러 코스에 있어도 하나만 `cleared`면 외운 것으로 친다.
- **카탈로그 무결성**: `cards.json`의 **모든 `verses` ref가 실제 절로 해석된다**(오타 검출).
- **깨진 항목 내성**: ref 하나가 해석 불가여도 나머지로 등급이 계산되고 앱이 죽지 않는다.
- **축하 1회 가드**: 같은 등급은 다시 뒤집히지 않고, 등급이 오르면 다시 뒤집힌다.
- **결과 화면**: green 판정으로 등급이 오르면 뒤집기가 뜨고, 안 올랐으면 뜨지 않는다.
- **도감**: 등급 없음 카드는 화면에 없고, 상세에 절 목록·진행 숫자가 **없다**.

---

## 8. 범위 밖

- **카드 설명·관련 절 목록 확정** — 사람이 채울 데이터다. 이 작업은 기존 6장에
  로직 확인용 자리표시 값만 넣는다.
- **실제 카드 아트** — 기존 스펙대로 플레이스홀더까지만.
- **등급별 아트 차등**(같은 카드의 등급마다 다른 그림) — 넣지 않는다.
- **가챠·재화·중복 교환**, 서버 카탈로그 원격 갱신 — 기존 스펙 §9 그대로 범위 밖.

# 앱 랜딩페이지 설계 가이드 (참고 자료 + PixBible 적용안)

작성일: 2026-07-28

## 출처

디자인나스(`designnas_official`)의 "전환률이 높은 앱 랜딩페이지 설계가이드" 스레드 게시물
(2026-01-13, 조회 4.3만).
<https://www.threads.com/@designnas_official/post/DTbwDOqk1rN>

본문이 이미지 캐러셀 7장으로 되어 있어 아래는 요점을 정리한 것이다. 원문 표현이 아니라
요약이며, 정확한 워딩은 원 게시물을 참고할 것.

## 가이드 요약 — 위에서 아래로 11개 블록

권장하는 페이지 구성 순서다.

1. **내비게이션 바** — 상단 고정 메뉴 + 우측 CTA 버튼.
2. **히어로 (좌측)** — 명확한 헤드라인, 가치 제안 한 줄, 그리고 앱스토어 다운로드 버튼.
   방문자가 첫 화면에서 바로 "스크롤하거나 다운로드하고 싶게" 만드는 것이 목표.
   다운로드 수 같은 성과 지표를 버튼 아래 작게 덧붙임.
3. **히어로 (우측)** — 앱 미리보기 화면 또는 스마트폰 목업. 사용자가 무엇을 기대할 수
   있는지 시각적으로 보여준다.
4. **신뢰 로고 바** — 함께하는 유명 파트너·고객사 로고를 나열해 짧은 시간에 신뢰를 만든다.
5. **Features 섹션** — 비주얼과 설명이 함께 담긴 주요 기능 카드. 앱이 실제 문제를 어떻게
   푸는지 빠르게 보여준다. 큰 카드 1개 + 작은 카드 2개 식의 비대칭 배치.
6. **Why Choose Us 섹션** — 아이콘 + 짧은 제목 + 혜택 중심 문구를 4열로. 다른 앱이 아니라
   이 앱을 골라야 하는 이유를 명확히 전달.
7. **리뷰 섹션** — 이름, 평점(별), 짧은 후기가 담긴 카드. 진정성과 신뢰를 쌓는 역할.
8. **FAQ 섹션** — 접을 수 있는(아코디언) 질문 목록. 레이아웃을 복잡하게 만들지 않으면서
   자주 묻는 우려를 해소한다.
9. **마지막 CTA** — 다운로드 혜택과 앱의 가치를 다시 강조하고, 앱스토어 버튼을 한 번 더 배치.
10. **CTA 옆 비주얼** — 휴대폰 목업이나 일러스트를 함께 놓아 분위기와 몰입감을 유지.
11. **푸터** — 저작권 표기와 SNS 링크.

## PixBible 적용안

현재 랜딩([verse-web-next/app/[locale]/page.tsx](../verse-web-next/app/%5Blocale%5D/page.tsx))은
히어로(타이틀·태그라인·CTA 2개) + 기능 카드 4개, 두 섹션뿐이다. iOS 앱이 출시되었으므로
앱 다운로드를 주 전환 목표로 삼아 재구성한다.

App Store: <https://apps.apple.com/kr/app/pixbible-bible-verse-memory/id6791622201> (id6791622201)

| # | 가이드 항목 | PixBible 적용 |
|---|---|---|
| 1 | 내비게이션 바 | 이미 있음 — 변경 없음 |
| 2 | 히어로 + 앱스토어 버튼 | **재작성.** App Store 배지를 주 CTA로, "웹에서 먼저 해보기"를 보조 링크로 강등 |
| 3 | 앱 미리보기 목업 | `docs/store-assets/screenshots-6.5/` 기존 스크린샷 재활용 |
| 4 | 파트너 로고 | **해당 자산 없음.** 실제 지표(KJV 66권 / 코스 수 / 암송 모드 4종)로 대체 |
| 5 | Features 섹션 | 기존 기능 카드 4개 재활용 + 스크린샷 곁들이기 |
| 6 | Why Choose Us | 5번과 내용이 겹침 → **통합**, 별도 섹션 만들지 않음 |
| 7 | 리뷰 섹션 | **보류.** 출시 직후라 실제 후기 없음. 리뷰가 쌓이면 추가 |
| 8 | FAQ 섹션 | **보류.** 1차 구현 범위에서 제외 |
| 9 | 마지막 CTA | 신규 — App Store 배지 재배치 |
| 10 | CTA 옆 비주얼 | 스크린샷 재사용 |
| 11 | 푸터 | 이미 있음([Footer.tsx](../verse-web-next/components/Footer.tsx)) — 변경 없음 |

### 지켜야 할 원칙

- **4번과 7번은 없는 것을 지어내지 않는다.** 가짜 파트너 로고나 가짜 후기는 넣지 않는다.
  4번은 검증 가능한 실제 숫자로 대체하고, 7번은 실제 리뷰가 생길 때까지 비워둔다.
- 기존 레트로 픽셀 스타일(각진 테두리 + 하드 그림자, `landing-feature-card`)을 유지한다.
  가이드의 예시 시안은 둥근 모서리의 모던 스타일이지만, 그대로 따라가면 앱과 톤이 어긋난다.
- 문구는 `messages/ko.json` · `en.json`의 `landing` 네임스페이스에 키를 추가해 양쪽 언어를
  모두 채운다.
- 안드로이드는 아직 미출시이므로 Google Play 배지는 넣지 않는다. 가이드 시안에는 배지가
  두 개지만 iOS 하나만 둔다.
